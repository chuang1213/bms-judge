# PHASE4B_PLAN.md — 谱面表示实验计划

> 2026-09-12。配套：`PHASE4B_REFERENCES.md`（调查）、`PHASE4_PROTOCOL.md` §11（协议）。
> **本文件是计划，不是实现。等用户确认后才写代码。**

## 0. 一句话

先做两件**几乎免费**的事把数据铺满（MSD 扩覆盖 ≈秒级、perm_space 扩覆盖 ≈12 分钟），
然后在**同一批行 / 同一 split / 同一 seed** 上比较 4 个特征族 × 2 个模型类，
用 Phase 4B 已有的两道门 + 玩家内指标 + 置换检验判定。
**不做 framework 七轴，不移植 panchira 的 Rust，不先上深度学习，不启动推荐器。**

## 1. 调查结论对计划的三个硬约束

1. **`cs_*` 26 列 = `OBJECTIVE_STAT_COLS` 去掉 `c_jrank`**（实测确认：缺的正是 `c_jrank`，没有多余的）。
   `c_jrank` 是难度表等级，在协议红线上，**必须继续排除**。所以"客观统计"这一族已经定稿，不需要再动。
2. **MSD 已经撞上限**：现有 5,497 行里 `msd_overall` 有 **12 张谱 = 40.00**，
   另有 `handstream` 10、`stamina` 4、`stream` 1、`chordjack` 1 张撞顶。
   `msd_overall` 最大值 41.31 说明上限不是硬墙但有截平。**扩覆盖后必须先做饱和度检查**，
   否则最难的那一段谱在特征上被压成同一个值。
3. **MSD 只覆盖 42.7% 的行**（991/2345 谱在 Phase 4B 上次的 cold_chart 测试集里）。
   任何用到 MSD 的结论都只在那个子集上成立，**必须单独报告子集规模**，不能和全量数字混着读。

## 2. 第 0 阶段：把数据铺满（不做模型）

**目标：把 MSD 和 perm_space 从 Phase 3 的"围栏范围"扩到 Phase 4B 的"cross_section 范围"。**

| 步骤 | 输入 | 输出 | 实测成本 |
|---|---|---|---|
| 0.1 MSD 扩覆盖 | cross_section 里 `mode_kind=='sp'` 的唯一 sha256 = **12,292**（现有 5,254，**补 7,038**） | `output/phase4/dataset/msd_full.parquet` | 打包 ~1 分钟；WASM **≈5 秒** |
| 0.2 MSD 饱和度检查 | 上一步输出 | 报告：每轴 = 40.00 的谱数、是否集中在高段 | 秒级 |
| 0.3 perm_space 扩覆盖 | 同上（现有 4,262，**补 ~7,900**） | `output/phase4/dataset/chart_perm_space_full.parquet` | **≈12 分钟**单进程，可用 12 worker 降到 ~1.5 分钟 |
| 0.4 特征拼接审计 | 三个 parquet + cross_section | 一份 `features_audit.json`：每列覆盖率、缺失模式、与 `cs_*` 的相关系数 | 秒级 |

**硬性要求（协议 §11.2 + 用户指令）**：
- 缺 MSD / 缺 perm 的谱**保持 NaN**，**禁止填 0 或均值**；覆盖率必须写进每个结果 JSON。
- 不改 `ref_repo/` 里的 WASM。
- 扩覆盖**不改公式**，只改输入清单；如果发现公式要和 Phase 3 不同，那是另一个决定，需单独说明。

**0.2 的决策点**：如果饱和度检查显示撞顶谱集中在高段（预期如此），
则复制一份 WASM 到我们自己的目录、跑 `patch-minaclac-msd-cap.mjs` 把上限 40→100，
**用打过补丁的版本再算一遍**，并报告"补丁前/后"两组数字。
注意：patch 脚本是 MIT 项目的工具，WASM 本身来自 Etterna（GPL-3），
**只在本地实验使用，不再分发**，并在报告里注明。

## 3. 实验矩阵

### 3.1 特征族（5 族）

| 代号 | 特征 | 列数 | 覆盖 | 备注 |
|---|---|---|---|---|
| `obj` | `cs_*` 客观统计 | 26 | 100% | 已定稿（= `OBJECTIVE_STAT_COLS` 去 `c_jrank`） |
| `msd` | MinaCalc 7 轴 | 7 | 扩后 ~99% | 外部程序，Etterna 校准 |
| `perm` | `ps_*` 排列空间 | 22 | 扩后 ~99% | Phase 3 已实现，跨谱可比 |
| `v2` | `v2_*` 客观统计 v2 | 14 | 需重算 | IOI/NPS/同时押/熵/手平衡；**是否纳入待定**（见 §4） |
| `fw` | framework 七轴 | — | — | **本轮不做**（见 `PHASE4B_REFERENCES.md` §C） |

组合（按协议 §11.5"每加一层都要胜过上一层"）：
`obj` → `obj+msd` → `obj+msd+perm` → （可选）`obj+msd+perm+v2`。

### 3.2 模型类（2 类，不先上深度学习）

| 代号 | 模型 | 为什么 |
|---|---|---|
| `ridge` | Ridge（标准化后），α 在**训练集内部**用 K 折选 | 线性、可解释系数方向、便宜 |
| `gbdt` | HistGradientBoostingRegressor | 处理缺失值原生（**MSD 的 NaN 不用填**）、非线性、当前最强基线 |

**两条必须守住的规则**：
1. **同一批行**：在同一 track 内，所有特征族用**完全相同的行集**（取交集），否则又是上次那个"不同特征集在不同行上比"的坑。
2. **同一 split / 同一 seed**：复用 `phase4/splits.py`（唯一定义来源），不新写分裂。
3. Ridge **不能吃 NaN** → 对 MSD/perm track，取交集行；GBDT 可以直接用 NaN 但为公平也取交集。
   `obj` track 保持全量，因为它是 100% 覆盖的基准。

### 3.3 评估

**两道门（照搬 `phase4b/run_phase4b.py`，不新写判定逻辑）**：

- **第一道门（谱面级难度）**：目标 = 去掉表演者水平后的**谱面平均残差**；
  必须在**同一批行**上胜过该 track 的 `content_ridge`（in-protocol 版本，不是那个冻结的 6.243）。
- **第二道门（玩家×谱面交互）**：`content_noninteractive` vs `content_x_player`；
  必须看**玩家内 MAE / 玩家内 Spearman / NDCG@10**；
  只看总体 MAE 改善而排序不动 → 判 `difficulty_only`，**不过**。

**指标（全部保留）**：
- 总体 MAE / RMSE、**玩家内 MAE**、**玩家内 Spearman**、**NDCG@10 / @20**；
- **置换检验**（打乱测试行的谱面内容后必须变差）——继续保留，这是防自欺的关键；
- 每 track 的**行数 / 谱面数 / 玩家数**（上次就是因为没记这个才比错）。

**seed 与稳定性**：≥3 seed；沿用"每个 seed 都赢过基线均值 **且** 提升 > seed 标准差"才算稳定。

**LR2**：只有 2 名玩家。**只报数字，不做统计结论**，不参与任何通过/不通过判定。

## 4. 工作量与执行顺序（按"成本 / 信息量"排序）

| 顺序 | 任务 | 成本 | 预计信息量 | 是否可能进最终表示 |
|---|---|---|---|---|
| **1** | 0.1–0.2 MSD 扩覆盖 + 饱和度检查 | **分钟级** | **高**：直接回答"5.81 是特征不够还是模型到顶" | 是（候选输入） |
| **2** | `obj` vs `obj+msd` vs `obj+msd+perm` 三 track 跑两道门 | 小（复用现成脚本） | **高**：这是主结果 | `obj+msd(+perm)` 可能 |
| **3** | 0.3 perm_space 扩覆盖 | 12 分钟 | 中：perm 只在补齐后才有意义 | 是（候选输入） |
| **4** | `perm` 单独成族 + 边际信息检查 | 小 | 中：回答"手部几何有没有独立信号" | 待定 |
| **5** | `anchors[7]` / `trills[21]` 是否移植 | 0.5–1 天（若要） | 低–中：`anchors` 与现有 lane 计数高度共线；`trills` 可能新 | 大概率不进 |
| **6** | `v2` 特征族（重算 14 列） | 半天 | 中 | 待定 |
| **7** | framework 七轴 | **6–8 天** | 低（且无法验证） | **不做** |
| **8** | note sequence / 原始事件学表示 | 天级 | 未知 | 协议 §11.5 第 2 层，**门过之前不动** |

**明确只做基线、不进最终表示的**：`msd_overall` 单列基线、framework 七轴（若将来做）、任何"单谱内归一化"的变体。

**边际信息检查（顺序 4 的做法）**：对 `perm` 与 `obj` 的每一列算两两相关，
报告 `perm` 里有没有与 `obj` 相关性 < 0.7 的列。**如果没有，就说明 perm 基本被 obj 吃掉，不必进最终表示。**

## 5. 停止条件

按协议 §11.6 + 用户指令：

1. **第一道门**：组合特征必须**稳定超过**同 track 的 `content_ridge`；
   赢不了 → 该组合出局，不加下一层。
2. **第二道门**：必须同时改善**玩家内 MAE 和玩家内排序**；
   只改善谱面级 MAE → 判 `difficulty_only`，**不过**。
3. **如果参考特征（MSD / perm）都不能稳定超过现有 26 统计 GBDT 基线** →
   **不进入 M5 推荐器**，直接写负结果：
   "当前可获取的谱面内容不足以支撑个性化预测"。
4. **如果两道门都过** → 也不自动做推荐器；推荐器需要单独申请（协议 §11.6）。
5. **任何一层复杂度没赢过上一层基线就停下**，不靠调参硬凑。

## 6. 明确不做的事

- 不做 framework 七轴（成本 6–8 天、撞红线、且**无法在本项目验证正确性**——没有 character 真值）。
- 不重测 felt-time（Phase 3 已证不适用）。
- 不搬运 Permikon 的 Rust/WASM（**无许可证**）。只沿用 Phase 3 已有的 Python 实现。
- 不照搬 panchira 的单谱 min-max 归一化（摧毁跨谱可比性）。
- 不用难度表等级作特征（`c_jrank` 继续排除）。
- 不填 MSD/perm 的缺失值。
- 不改 `ref_repo/` 里的任何文件。
- 不启动 M5 推荐器。
- 不手工定义技能轴作为最终表示。

## 8. 等确认的问题

1. **要不要打 MSD 上限补丁（40→100）？** 我的建议：**先做饱和度检查再定**。
   如果撞顶谱集中在高段（sl11-12 / st8+），就打——因为 BMS 的难度信号正好在那一段。
2. **`v2`（14 列客观统计 v2）要不要纳入？** 我的建议：**纳入，但排在 MSD/perm 之后**。
   它便宜（一次解析）且是已实现代码，边际成本低。
3. **`trills[21]` 要不要移植？** 我的建议：**先做边际信息检查再定**。
   它是 panchira 里唯一明显还没被我们覆盖的量，但 21 列稀疏特征容易过拟合。
