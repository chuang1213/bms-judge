## 2. 数据层（第 3 步）

`bms_ml/output/phase4/dataset/cross_section.parquet`：**45,863 行**
= beatoraja 40,446 行 / 16 名玩家 + LR2 5,417 行 / 1 个存档。

构建中必须解决、且已实测确认的口径问题（详见 `build_cross_section.py` docstring）：

1. **beatoraja 不需要"折叠成最佳"**：`score.db` 的 `score` 表就是每谱一行当前最佳。
   真正的游玩日志 `scorelog.db` 是**改善日志**（只在刷新纪录时才有一条），且 `score`
   列与判定计数不同量纲（比值中位 0.98、离散度很大），所以不作数据源。
2. **beatoraja 没有 acc 列，公式必须含大型判定**：
   `acc = (2*(epg+lpg) + (egr+lgr)) / (2*Σ判定) * 100`。
   若照搬 LR2 的 `(epg*2+egr)`，中位只有 45.6%、最大出现 **304%** 的假值；
   含 `lpg/lgr` 后 18 份存档全部落在 [0,100]，中位 75.5%。分母用判定总和而非 `notes`，
   因为 `notes` 与判定总和在约 15% 的行上不一致（比值中位 0.99）。
3. **哈希长度**：`score.db`/`scorelog.db` 里存在 256/192/67 字符的 sha256，
   不是语料库 BMS 文件哈希，全部丢弃（chuang 丢 94 行、muiclac 丢 181 行）。
4. **同一 sha 多个 mode**（同一张谱带不同 assist 选项各记一次）：保留**最好**的一条
   （先 acc、再灯标、再 BP），共折叠 341 行。
5. **音符数分母**：主口径用各客户端自记音符数，`acc_alt` 是换到 manifest 音符数的变体。
   稳健性检查：`acc_alt` 下门基线 MAE 6.380（主口径 6.328），结论不变。
6. **LR2 目录里有别人的存档**：`PlayerData/LunaticRave2/` 同时有 `V_soflan.db` 和
   `mengye.db`（另一个玩家）。已在 `players.json` 给该条加 `db_file: V_soflan.db` 明确钉住，
   避免把别人数据挂到 vsoflan 名下。

**缺席数据**：`steve`、`taffy`、`buzhang` 没有 `score.db`（只有 scorelog.db），
无法重建当前最佳，本阶段缺席 → beatoraja 从 18 人降到 **16 人**。这是数据缺口，不是我做的取舍。

## 4. 四 split + 固定基线（第 5 步）

`bms_ml/output/phase4/evaluate_matrix.json`。行过滤：非 SP 模式 −2,061 行、判定<120 −196 行、
`playcount==0` −75 行（没打过的不算观测），beatoraja 剩 38,176 行 / 11,723 谱。
所有基线只在训练行上拟合（有回归测试强制验证这一点）。

### beatoraja（MAE，越低越好；3 seed）

| split | global_mean | player_mean | chart_mean | **player+chart_bias（门）** |
|---|---|---|---|---|
| random_interaction | 7.93 | 6.68 | 7.98 | **6.33 ± 0.01** |
| loo_chart_per_player | 9.08 ± 1.78 | 6.55 ± 1.22 | 9.39 ± 1.23 | **6.24 ± 1.08** |
| cold_player | 8.97 ± 0.66 | = global | **8.06 ± 0.80** | = chart_mean |
| cold_chart | 7.94 ± 0.13 | **6.75 ± 0.12** | = global | = player_mean |

读法：
- **门基线 = 6.33 ± 0.01**。玩家偏差贡献最大（7.93 → 6.68），谱面偏差再补 0.35pp。
- **谱面均值单独几乎没用**（7.98，等于全局 7.93）：谱面平均成绩主要由"谁打了它"决定。
  这直接说明**冷谱面靠矩阵结构是无解的**——`cold_chart` 一栏里谱面效应恒为 0，
  基线退化成玩家均值 6.75，任何矩阵补全在这一栏都拿不到信息。要冷谱面必须上内容编码器，
  而按协议那是 M4/M5 的事。
- **冷玩家**：谱面均值（8.06）优于全局均值（8.97），即"这张谱对其他人多难"能迁移；
  但差距只有 0.9pp。
- `loo_chart_per_player` 的 n_test = 16，seed 波动 ±1.08pp **大于**模型间的正常差距，
  单看这个 split 不可下结论，必须多 seed（协议已写明）。

### 逐玩家（random_interaction，门基线）

MAE 从 MRCA 3.44 到 vsoflan 8.24，**跨玩家差 4.8pp**，即聚合数字掩盖了 2.4 倍的差异。
最难预测的是 vsoflan(8.24)、wufe8(7.03)、LED(6.80)。vsoflan 恰好也是 LR2 存档的同一人。

### 辅助指标（门基线，seed 0）

- 校准：预测最低十分位偏乐观 5.8pp，最高十分位偏乐观 3.0pp，中段 |gap| ≤ 1.7pp。
  即**两端都系统偏乐观**（低分谱被高估更多），预测落在 ±5pp 内的比例 0.37–0.64。
- 排序：玩家内 Spearman 均值 0.455；NDCG@5/10/20 ≈ 0.91–0.92；
  Precision@K 均值 0.20–0.27（K=10 时 0.206，随机水平约 10/需排序集合大小，
  所以有信号但不强）。

### LR2（1 个玩家）

四栏全部退化：`player_mean` = `chart_mean` = `player_chart_bias` = `global_mean`（MAE 12.79 ± 0.70），
`cold_player` 无定义（训练集为空），`loo_chart_per_player` 只留 1 格。
**结论：单玩家矩阵上无法评估矩阵补全**，JSON 里已写入 `identifiability` 说明。
另外 LR2 的 MAE（12.79）明显比 beatoraja（6.33）差，但其 acc 的 sd 是 18.8 对 10.9，
相对误差其实同一量级——**不要**把两个数字直接比。

## 5. 对用户机器学习基础的说明（为什么这么做）

- **为什么必须有基线**：如果"补全矩阵"只报自己的 MAE，我们无法知道它是否只是把
  "这个玩家平均打 77 分"换了个说法。所以先造 4 个只会背平均值的基线，模型必须超过它们。
- **为什么门基线是"玩家偏差+谱面偏差"而不是玩家均值**：它是"完全不加表示、只用两个
  偏差项"的最强版本，也是最难超过的。超过它才说明模型学到了偏差之外的交互结构。
- **为什么分四栏**：随机遮盖（训练时见过该玩家和该谱）和冷谱面（都没见过）是两种
  完全不同的问题。混在一起报一个数字，会把"记住了玩家平均分"误读成"预测出了谱面难度"。

## 6. 不确定 / 未验证的地方

- 判定计数与 `notes` 在约 15% 行上不一致，我选择了判定总和作分母。**没有**独立验证
  哪一个是"真值"，只验证了用它算出的 acc 稳定落在 [0,100] 且中位合理。
- `acc_alt`（manifest 分母）只做了单 seed 稳健性检查，且对 2,257 行有 >1pp 的差异。
- beatoraja 谱面效应里混着"这张谱有多流行"（打的人多 → 均值更可靠），
  门基线不区分这两者。M3 之后的诊断应把"谱面效应"与"观测数"分开看。
- `cold_chart` 一栏的基线退化是我设计的直接后果（谱面效应恒为 0）。这不是 bug，
  但它意味**这一栏现在无法评价任何东西**；要不要给它一个"谱面 popularity 先验"
  作基线，属于协议之外的新决定，需要用户确认。
- `loo_chart_per_player` 只留 1 格/玩家，噪声太大。建议 M3 增加一个
  `loo_k_charts_per_player`（k=5/10）变体，但这是改协议，未擅自加。
