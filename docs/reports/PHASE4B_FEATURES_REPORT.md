# PHASE4B_FEATURES_REPORT.md — 特征族实验结果

> 2026-09-12。协议：`PHASE4_PROTOCOL.md` §11；计划：`PHASE4B_PLAN.md`；调查：`PHASE4B_REFERENCES.md`。
> 本文件报告第 0 阶段（特征铺满）+ 特征族实验矩阵的结果。
> **M3（矩阵补全）仍然是失败的**；Phase 4B 是独立分支。

## 0. 一句话结论

**两道门都过，但只有 MSD 真正加了新信息。**
在 beatoraja 同一批 37,924 行上：26 统计 GBDT 冷谱面 MAE **6.037**，
加 MSD 降到 **5.929（唯一稳定改善，+0.109 = seed 波动的 2.6 倍）**；
再加 perm / v2 **没有进一步改善**（5.932 / 5.911，涨幅小于 seed 波动）。
**perm 单独用比统计基线还差（6.776 vs 6.638）**——它基本被统计量吃掉了。
交互门（第二道门）在所有特征族上都过。

**按停止条件：不继续堆 note-sequence。** 参考特征没有"稳定超过 26 统计 GBDT"到值得再投入的程度。

## 1. 第 0 阶段：特征铺满（成本 分钟级）

| 特征表 | 行数 | 对 12,292 张 SP 谱的覆盖 | 成本 |
|---|---|---|---|
| `msd_cap100.parquet`（打补丁） | 12,192 | **99.2%** | 打包 ~1 min + WASM **7.9 s** |
| `msd_cap40.parquet`（原版对照） | 12,192 | 99.2% | WASM 4.9 s |
| `perm_space_full.parquet` | 12,219 | **99.4%** | **~35 min**（7987 张） |
| `chart_stats_v2_full.parquet` | 12,221 | **99.4%** | ~3 min（29 行因缺 sequence 为 NaN） |

**为什么原来只有 5,497 / 4,262**：`msd_prep.py` 与 `chart_stats_v2.py` 按 Phase 3 的
"围栏表 ∪ 已打谱"取清单（6,509 张）。换成 Phase 4B 的 cross_section SP 清单即可，
**管线本身一行没改**。MSD 的 8,938 张新谱只花了 **7.9 秒**。

### 1.1 MSD 上限补丁（按用户决定执行）

先做饱和度检查，结论支持打补丁：

- 旧范围 5,497 张里 **11 张撞顶**（0.20%），集中在 **stella 10 / 11 / 12**、**overjoy 6 / 8**；
- `handstream` 撞顶最多（10 张）；
- 打补丁后（40 → 100）**在 12,192 张里 0 张撞顶**；
- 补丁前后逐行比较：**11 张谱的 `msd_overall` 变化，最大 +7.60**（41.48 → 48.48），
  `handstream` +7.90、`chordjack` +7.75、`jumpstream` +7.56。

**只有 11 张谱受影响，但每张涨 3–8 个 MSD 点**——不补丁会让这批高段谱被压成
与真实难度明显不符的值。**主结果用 `cap100`，`cap40` 作对照，两者永不混列。**

补丁实现：把 WASM 复制到 `output/phase4/features_build/ett_patched/` 再改字节，
**`ref_repo/` 未被改写**。

### 1.2 顺手修掉的两个坑

1. **`msd_technical` 是死列**：在 12,192 张谱上只有 **4 个不同取值**（0.18 占绝大多数）。
   Phase 3 的"常数则丢弃"检查跑在**单批新算的行**上，所以它漏了过去。
   已改为在合并后整表检查并丢弃，并加断言"必须只剩 7 轴"。
2. **`msd_cap` 是溯源列不是轴**：饱和度检查一开始把 `msd_cap` 当轴，
   而它恒等于上限值，于是**每一行都被判为撞顶**。已排除。

## 2. 实验矩阵（同一批行、同一 split、同一 seed）

- 模型：Ridge（α 由训练集内 5 折 CV 选）/ GBDT（`max_iter=300, lr=0.06, depth=3`，参数未调）
- 缺失值**不填**：GBDT 原生处理 NaN；Ridge 用该 track 的**共同覆盖行**
- 覆盖两层：`full`（该族全部行）与 `common`（所有族都有特征的行）
- **主结论层 = common，且 `common` 只由高覆盖族（obj / msd / perm）定义**

> 一个必须说明的修正：第一版把 `v2` 也算进 common 的定义，结果共同行从 37,924
> **塌到 10,021（26%）**，而且那是个**更容易的子集**（参考基线 MAE 6.60 vs 6.80）。
> 这会让"同批行比较"变成"在简单子集上比较"。现在 common 由高覆盖族定义（99.3%），
> `v2` 单独报它自己的行与这个共同集。

### 2.1 beatoraja 冷谱面难度（第一道门）— common 层，37,924 行 / 16 玩家

| 特征族 | Ridge MAE | Ridge 增益 | **GBDT MAE** | GBDT 增益 | 稳定？ |
|---|---|---|---|---|---|
| 参考基线（26 统计 content_ridge） | — | — | 6.6376 | — | 参考 |
| `perm`（22 列） | 6.9325 | −0.2949 | 6.7762 | **−0.1386** | ✗ |
| `msd`（7 列） | 6.6384 | −0.0008 | 6.2400 | +0.3976 | ✓ |
| `obj`（26 列） | 6.6458 | −0.0082 | 6.0372 | +0.6004 | ✓ |
| **`obj+msd`（33 列）** | 6.4113 | +0.2263 | **5.9290** | **+0.7086** | ✓ |
| `obj+msd+perm`（55 列） | 6.2594 | +0.3782 | 5.9315 | +0.7061 | ✓ |
| `obj+msd+perm+v2`（69 列） | 6.1496 | +0.4880 | 5.9111 | +0.7265 | ✓ |

**读法（每条都对照"上一层"）：**

1. **`msd` 单独就能大幅超过参考基线**（6.640 → 6.240），7 列打败 26 列。
   这印证了调查里的判断：MinaCalc 是社区校准过的难度模型，信息密度很高。
2. **`obj` + `msd` 是最好的组合**：5.929，比只加 obj 再降 **0.108**。
3. **`perm` 单独是负结果**：6.776/6.933，**比参考基线还差**。
   它没有独立信号——Phase 3 的 perm_space 基本被 26 个客观统计吃掉了。
4. **加 `perm` 到 `obj+msd` 上：5.9315，比 5.9290 差 0.0025**（噪声级）。
   → **perm 不进最终表示**。
5. **加 `v2`：5.9111，比 5.9290 好 0.018**，但 (a) 只在 26% 的行上可得，
   (b) 差异远小于 seed 波动。→ **边际检查不通过，v2 不进最终表示**。
6. **Ridge 全线不如 GBDT**，且 Ridge 在单族上全部失败（包括 obj）。
   这说明信号是非线性的；也再次确认 **Phase 4B 上一轮 ~1pp 的提升主要来自换模型类**。

### 2.2 beatoraja 玩家×谱面交互（第二道门）— common 层

| 特征族 | 非交互 玩家内MAE | 交互 玩家内MAE | 增益 | 玩家内 Spearman（非/交互） | 排序增益 | 判定 |
|---|---|---|---|---|---|---|
| `obj+msd` | 5.670 | **5.110** | +0.560 | 0.543 → **0.616** | +0.073 | **过** |
| `obj+msd+perm` | 5.669 | 5.098 | +0.571 | 0.544 → 0.619 | +0.075 | 过 |
| `obj+msd+perm+v2` | 5.645 | **5.070** | +0.575 | 0.549 → **0.627** | +0.078 | 过 |
| `obj` | 5.794 | 5.333 | +0.460 | 0.503 → 0.564 | +0.061 | 过 |
| `msd` | 5.905 | 5.390 | +0.515 | 0.470 → 0.559 | +0.089 | 过 |
| `perm` | 6.445 | 6.197 | +0.248 | 0.221 → 0.283 | +0.062 | 过（但最弱） |

**所有族都通过了交互门，且没有一族被判为 `difficulty_only`。**
置换检验（打乱内容↔玩家的配对后重算）在所有配置上**都变差**：
例如 `obj+msd` 从 5.110 掉到 **5.670（≈非交互水平）**，`obj+msd+perm` 5.098 → 5.669。
**交互信号是真的，不是容量假象。**

注意 `perm` 的交互门数字最弱（玩家内 Spearman 只有 0.22–0.28），与它第一道门的失败一致。

### 2.3 LR2（2 名玩家）

**按计划只报数字，不做统计判定。** 数字与 beatoraja 同向
（`obj+msd` GBDT 第一道门 +1.397、交互门过），但 **2 个玩家无法支撑任何结论**，
`full` 层的"不过"与 `common` 层的"过"只是子集效应。

## 3. 停止条件判定

用户设定的停止条件：**参考特征不能稳定超过 26 统计 GBDT → 停止，不进入 M5，不继续堆 note-sequence。**

实测：`obj+msd`（5.929）**稳定超过** `obj`（6.037）——差值 0.108，是 seed 波动的 2.6 倍。
所以严格说，**停止条件没有被触发**（MSD 确实加了稳定信息）。

但是往上加层的收益塌得很快：

| 阶梯 | 同批行 GBDT MAE | 相对上一层 |
|---|---|---|
| `obj` | 6.0372 | — |
| `obj+msd` | 5.9290 | **−0.108（稳定）** |
| `obj+msd+perm` | 5.9315 | +0.0025（变差） |
| `obj+msd+perm+v2` | 5.9111 | −0.018（且只在 26% 行上） |

**结论：值得做的只有 MSD 这一层；perm 与 v2 应排除。**

## 4. 建议

**建议：以 `obj + msd`（33 列）作为冷谱面的候选表示收尾，不启动 note-sequence 编码器（M4 第 2 层），不启动推荐器（M5）。**

理由：
1. MSD 是唯一稳定有效的新信息，且它已经**扩到 99.2% 覆盖**；
2. perm 被证明与客观统计重复（单独用比基线差），v2 的边际收益淹没在 seed 波动里；
3. 继续堆表示的下一步是 note-sequence 学习，而它要证明的对手是 **5.929**，
   不是上一轮的 5.81——难度更高，且 Phase 2A 的预训练教训在案；
4. 剩余可做且便宜的事只有一件：把 MSD 覆盖从 **99.2% 补到 100%**
   （80 张谱缺 note sequence，属解析缺口）。

## 5. 不确定 / 未验证

- **GBDT 未调参**（固定 300/0.06/3），Ridge 的 α 只在 4 个候选里选。
  所以"MSD 有效"的方向稳定，**幅度不稳定**。
- **`v2` 只在 26% 的行上存在**，且那批行更容易。它的"边际不显著"结论
  受这个选择效应影响，没有做严格的同分布检验。
- **`trills[21]`（panchira 唯一未覆盖的输出）按用户指令未移植**，
  因为 MSD/perm/v2 的主结果已经表明边际收益在快速衰减。
- **MSD 的 LN 处理仍不准确**（LN 起点当 tap、忽略终点，Etterna 的 RC 取向）。
  本轮没有为 LN 谱单独评估。
- **难度表等级只用作坐标**（饱和度检查的 tier 分组），从未作为特征；
  `c_jrank` 始终排除。
- **Phase 4B 的 `content_ridge` 参考数字与上一轮的 6.243 不可直接比较**：
  本轮是 in-protocol 重新拟合（6.6376 在 common 层、6.8021 在 full 层），
  上一轮冻结值来自不同的行过滤口径。
