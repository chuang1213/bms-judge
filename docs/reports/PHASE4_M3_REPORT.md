**M3 不通过。** 带偏差的矩阵分解（ALS）在 beatoraja 上没有稳定超过"玩家偏差+谱面偏差"

## 3. 为什么不过（数字背后的意思）

**这个数字在成绩表上是什么意思**：MAE 6.33 表示"预测某人在一张没打过的谱上能打多少分，
平均差 6.33 个百分点"（满分 100）。门基线只知道"这个人平均多强"+"这张谱平均多难"。
矩阵分解本应再学到"这个人 × 这张谱"的交互（比如某人擅长同时押、不擅长连打），
如果学到，MAE 应该明显下降、玩家内排序也应该变好。

三条证据说明它没学到：

1. **赢的部分几乎全是"正则化偏差"，不是交互**。把隐向量关掉、只保留被正则化的
   玩家/谱面偏差，random_interaction 的 MAE 是 **5.960**——比带隐向量的 6.132 **还好**。
   也就是说 6.33 → 5.96 这 0.37 的改善来自"门基线用未正则化的组均值、噪声大"，
   而不是矩阵补全的功劳。隐向量反而拖累了 0.17。
2. **玩家内排序没变好，random_interaction 上还变差了**（0.4540 vs 0.4561）。
   这正是补丁 2.2 要防的假通过：总体 MAE 好看一点，但排序能力没变。
3. **超参选择不是主因，但确实是第二层问题**。内层验证一致偏好弱正则（reg≈0.3），
   而真实测试集偏好 reg≈1–3。差距有多大：random_interaction 上按内层选 → 测试 6.129，
   按测试集作弊选 → 5.900，gap 0.23。**即使作弊也只有 5.90**，仍不足以在
   "稳定"标准下赢过 5.96 的收缩偏差基线，更没能改善排序。所以 M3 的失败
   首先是模型/信号问题，调参救不了。

## 4. 唯一明确的阳性信号：冷谱面内容基线

`cold_chart` 一栏里谱面在训练集中完全没出现，矩阵补全理论上拿不到信息（谱面偏差恒为 0），
这也被实测确认：`player_chart_bias` = `player_mean` = 6.749（完全退化）。

协议补丁 2.3 要求的**内容基线**（只用 26 个客观谱面统计 + 玩家偏移，不用难度表等级）：

| 模型 | cold_chart MAE |
|---|---|
| 门基线（退化成玩家均值） | 6.749 |
| MF(ALS) | 6.678 |
| **内容基线 content_ridge** | **6.243** |

**这是本轮唯一稳定的改善：7.5% 相对提升，三个 seed 一致。**
它的含义是：一张没被任何人打过的谱，光看它的客观统计（音符数、NPS、BPM、连打比例等）
就能比"猜该玩家平均水平"准 0.5 个百分点。

**但它的正确归属是 M4 的入场理由，不是 M3 通过。** 按协议停止线，M3 未过就不得开始 M4 —— 
这一点需要用户决定：是要破例让 M4 带着这个阳性信号继续，还是严格执行停止线先停下。

## 5. 对用户机器学习基础的说明

- **为什么"总体 MAE 好了"不算过**：MAE 主要由"这人多强"决定（本数据里跨玩家 MAE 差 4.8pp，
  远大于任何模型差距）。所以必须看**玩家内**指标：把每人的分数都减去他自己的平均水平后，
  模型还能不能判断"他在哪张谱上更好"。补丁 2.2 就是为此。
- **为什么"作弊网格"要单独报**：它回答"如果超参挑得完美能到多少"。它不能当结果，
  但它能区分两种失败——"方法不行"和"调参不行"。这里是前者占主因。
- **为什么门基线看着弱却难超**：它不需要学任何表示，只要有足够多观测，组均值就很准。
  本矩阵密度只有 5.4%，很多谱只有 1–2 人打过，所以**正则化过的组均值**（5.96）
  才是真正难对付的对手，而这跟"协同过滤"没关系。

## 6. 本轮的工程陷阱（已写进协议 §9，并有回归测试）

四个都会被静默地产生"看起来合理"的错误数字：

1. **玩家内 MAE 的第一版是假的**：`|(y-base)-(p-base)|` 恒等于 `|y-p|`，
   所以"玩家内 MAE"和普通 MAE 一模一样。必须对两侧都去均值。测试抓到了。
2. **ALS 两个因子块别名**：求解结果写进了"固定不动"的另一侧，目标函数震荡不降
   （训练 RMSE 6.0 → 1e7）。改成写入新数组后正常。
3. **分批 Cholesky 的残差塌缩**：一个错误 broadcast 把每组残差都换成第一个，解全为 0。
4. **单支撑度闭式解漏了 ‖g‖²**：`g·(gᵀr)/(reg+‖g‖²)` 写成了 `/reg`，整体缩放因子。

顺带：把逐谱的 Python 循环换成按支撑度分组的批量 Cholesky 后，拟合从
13–47 秒降到 0.2–6 秒（**30–150 倍**），这是能把 6 split × 3 seed × 30 网格跑完的前提。

## 7. 不确定 / 未验证

- **内层验证为什么偏好弱正则，我没有完全解释清楚**。已知它测的是"图表多、数据多"的条件，
  而外层测试是"新格子"条件，两者难度不同。我试了四种内层构造（随机格、整谱、
  按玩家随机交互、RMSE/MAE 两种打分）全都一致偏好弱正则。**没有找到正确的选择准则**，
  因此本轮把选择结果和作弊网格都报出来，而不是假装选择是对的。
- `content_ridge` 的 `alpha=1.0` 未调参，也没做特征消融。"内容有效"这个结论
  只在一组超参下验证过。
- LR2 的 2 玩家矩阵不足以判断协同过滤；`cold_player` 在 LR2 上只有 1 个训练玩家，
  数字不可解读。
- beatoraja 的谱面效应里混着"这张谱有多流行"，门基线不区分这两者。本轮没拆开。
